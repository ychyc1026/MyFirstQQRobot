# 用户身份、好友生命周期、历史授权与隐私

## 新旧好友判定

系统不使用“第一次给机器人发消息”来判断新好友，因为旧好友也可能第一次与新机器人程序交流。

可靠规则：

1. 机器人首次受控启动时读取一次好友列表，形成带时间与摘要哈希的基线；
2. 基线内的账号标记为 `existing_friend`；
3. 基线完成后收到 NapCat `friend_add` 事件的账号标记为 `new_friend`；
4. 没有基线时看到好友添加事件，只能标记为 `unknown`；
5. 主控号可以覆盖状态，但覆盖操作带来源、时间和审计；
6. 主控可解除人工覆盖，系统会回到最近一条好友基线或好友添加事件所支持的状态；没有强证据时回到 `unknown`，不会沿用人工结论；
7. 删除好友、重新添加等后续生命周期事件保留时间线，不覆盖历史事实。

状态只有四种：

- `existing_friend`：首次好友基线中已存在；
- `new_friend`：基线后有明确新增好友证据；
- `not_friend`：有明确非好友或删除证据；
- `unknown`：证据不足。

## 历史读取授权

默认策略为 `deny`，机器人不会因为对方是旧好友就自动读取全部聊天历史。

每个用户可以单独设置：

- `deny`：禁止实时读取；
- `file_import_only`：只能由主控在后台上传聊天导出文件；
- `selected_range`：允许指定起止时间和最大条数；
- `one_time`：一次性额度，用完自动回到禁止。

这些策略由统一访问门强制执行，不是界面提示。读取前按冻结状态、来源能力、条数、媒体权限和一次额度进行原子校验，允许和拒绝都写入 `data_access_log`。

NapCat 当前 `get_friend_msg_history` 只能按条数读取，无法在服务端严格限制日期。因此 `selected_range` 不允许直接调用实时接口，避免为了筛选目标日期而先读取范围外内容；它只能用于能在读取前确定边界的导入文件或后续受控适配器。

授权还要记录目的，例如“初始化用户画像”或“恢复最近会话上下文”。人格、记忆、空间内容分析不能借用另一个目的的授权。

## 隐私边界

数据按类别分别控制：公开资料、消息内容、上传文档、空间内容、派生记忆和用户专属人格。每类数据分别决定：

- 是否允许采集；
- 是否允许交给模型；
- 是否允许用于空间内容；
- 保留多少天；
- 是否被冻结；
- 能否导出或删除。

“冻结”立即阻止新的读取、模型使用和派生写入，但保留已有数据以便审计；“删除”是高风险异步任务，先生成影响预览和备份，再由主控二次确认。

## 主控 QQ 命令

```text
/用户 <QQ> 状态
/用户 <QQ> 标记旧友
/用户 <QQ> 标记新友
/用户 <QQ> 标记非好友
/用户 <QQ> 恢复自动判定
/用户 <QQ> 历史 禁止
/用户 <QQ> 历史 仅文件
/用户 <QQ> 历史 指定范围 <开始日期> <结束日期> <最大条数>
/用户 <QQ> 历史 一次授权 <最大条数>
/用户 <QQ> 历史 拉取
/用户 <QQ> 空间资料 状态
/用户 <QQ> 空间资料 禁止
/用户 <QQ> 空间资料 一次授权 <最大条数>
/用户 <QQ> 空间资料 限期 <天数> <最大条数>
/用户 <QQ> 空间资料 预览
/好友基线 状态
/好友基线 预览
/隐私 状态
/隐私 冻结 <QQ>
/隐私 解冻 <QQ>
/隐私 导出 <QQ>
/隐私 删除 <QQ>
```

指定范围、一次授权，以及空间资料一次授权/限期授权都会生成 30 分钟有效的审批码；主控再次发送 `/确认 <审批码>` 后才修改策略。好友关系不会自动打开空间资料读取。`/好友基线 预览` 只暂存好友号列表、数量和摘要哈希，经审批后才把账号标记为旧好友。

## 仪表盘页面

### 用户中心

- 新友、旧友、未知、非好友分组；
- 每个状态的证据和可信度；
- 首次观察、好友事件和主控覆盖时间线；
- 历史策略、人格、记忆、空间数据和主动消息入口。

### 好友生命周期

- 最新好友基线时间、数量和同步状态；
- 基线之后的新增、删除、重新添加和异常；
- 不确定用户待主控处理队列；
- 手动覆盖与恢复自动判定。

### 隐私中心

- 数据类别 × 用户的权限矩阵；
- 历史读取授权及到期时间；
- 冻结、导出、删除任务；
- 最近访问记录和被拒绝的读取请求，可按 QQ、决定和数据类别筛选；
- 导出与删除前备份的路径边界、字节数、SHA-256 和 JSON 数据包结构校验；
- 明确显示恢复边界：当前不提供一键恢复，只能经新审批后选择性重建；
- 全局默认值和用户例外。

## 当前状态

数据库与控制 API 已建立。`/用户 <QQ> 历史 拉取` 只在 `YCH_LIVE_HISTORY_ENABLED=true` 且该用户仍有一次授权时才会调用 `get_friend_msg_history`；结果只保留条数和访问日志，不落正文。首次好友基线仍须主控预览后再确认。`get_friend_list` 仍未作为自动采集入口。

仪表盘接口：

- `GET /api/v1/users/summary`：好友状态和历史策略汇总；
- `GET /api/v1/privacy/status`：隐私默认值、冻结状态和空间资料采集开关；
- `GET /api/v1/privacy/access-log`：脱敏访问决定、策略理由和聚合统计；
- `GET /api/v1/privacy/requests`：导出与删除任务列表；
- `GET /api/v1/privacy/requests/{id}/artifact/verify`：校验备份或导出产物完整性；
- `GET /api/v1/users/{qq}`：用户关系、历史/空间资料授权和身份依据；
- `GET /api/v1/users/{qq}/qzone-profile`：空间资料授权、快照和候选；
- `POST /api/v1/users/{qq}/qzone-profile/preview`：经授权后预览空间资料；
- `GET /api/v1/control/approvals`：待审批任务；
- `POST /api/v1/control/commands`：与主号 QQ 共用的命令入口。

包含用户详情、审批码或修改能力的接口必须使用独立 `YCH_ADMIN_ACCESS_TOKEN`。没有配置 token 时，修改接口直接禁用。
用户汇总和隐私状态也包含管理员级聚合信息，现与其他业务接口一样必须使用短时管理员会话；公开访问只保留健康检查和必要运行状态。

## 隐私归档保留与隔离

隐私导出、删除前备份和导入原文件归档已经纳入统一受管文件清单。系统先验证用户归属、受管路径、字节数、SHA-256、manifest/JSON/ZIP CRC，再检查活动导出、删除、审批、申诉和资料处理引用；任一项不确定都标记为阻止，不会成为清理候选。

隐私类默认没有自动保留候选，也不会静默删除。只有显式配置的类型策略才能产生预览；预览绑定当前管理员/主号、用户范围、进程实例、策略和引用修订，确认后只进入可恢复隔离区。网页不提供永久删除或把归档直接覆盖回运行库的按钮。跨用户枚举、绝对路径和原始 manifest 均不会进入 API DTO。

详细流程、失败回滚和重启对账见 `docs/MANAGED_ARTIFACT_RETENTION.md`。

已经实现并验证：

- 主号私聊和仪表盘共用统一命令总线；
- 好友状态人工覆盖、解除覆盖和证据审计；
- 好友基线预览、30 分钟审批和确认入库；
- 历史范围、一次授权、导出和删除的审批；
- 隐私冻结/解冻；
- 历史读取默认拒绝与访问日志；
- 历史一次/范围授权的 1–500 条硬上限与日期顺序双重校验；
- QQ 空间资料读取默认拒绝；好友关系不自动授权；只产生带过期时间的候选记忆；
- 一次授权并发安全消耗；
- 不支持日期范围的实时来源会被拒绝；
- 用户导出/删除覆盖主动消息、`target_uins` 定向空间帖，以及关联主号报告的运行时与事件；
  不误删好友可见/公开说说。
- 访问审计页只展示数据类别、调用目的、调用器、允许/拒绝和策略理由，不返回消息正文；
- 隐私产物可重新计算 SHA-256、字节数并验证 `ych-privacy-bundle-v1` 结构；上传原文件会进入
  `ych-private-file-archive-v1` ZIP，逐文件验证大小、SHA-256 和 ZIP CRC 后才允许删除；
- 控制命令、审批载荷和审计日志通过 `privacy_subject_links` 的结构化字段关联用户，不再使用
  JSON 文本 `LIKE` 猜测；关系 ID 冲突和隐私墓碑仍阻止安全的一键恢复。

仪表盘现已把判定来源、可信度和证据时间线放在同一张用户身份卡内，并提供好友基线预览、历史一次/范围授权、空间一次/限期授权与读取预览入口。点击好友基线或空间读取前会再次说明将访问的真实来源；授权类动作只改变策略，读取仍是独立动作。
审批详情只展示知情确认所需的受控范围字段（用户 QQ、条数、日期和有效天数），不把消息正文或其他任意载荷直接铺到审批页。
