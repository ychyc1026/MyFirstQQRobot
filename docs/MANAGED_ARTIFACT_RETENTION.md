# 受管文件清单、保留与可恢复隔离

## 覆盖范围

统一清单覆盖迁移备份、隐私导出、隐私删除前备份、数据库引用的导入原文件，以及 `storage/trash` 中的可恢复隔离批次。每项只向控制面暴露稳定 ID、类型、用户/系统范围、大小、校验/引用/保留状态和安全显示名；不暴露绝对路径、摘要、原始 manifest 或私密正文。

## 固定判定顺序

1. 路径必须位于已登记受管根目录，拒绝遍历、大小写绕过、符号链接、junction/reparse 逃逸。
2. 重新读取当前字节数和 SHA-256，并执行类型校验：SQLite `quick_check`、manifest、JSON bundle 或 ZIP CRC。
3. 查询活动工作流引用。导出、删除、审批、申诉、迁移回滚窗口、资料任务和未解决隔离调查都会保护文件。
4. 完整性和引用均安全后才应用类型保留策略。损坏、缺失、跨用户或状态未知一律阻止。

迁移备份保留最新 3 份，仅把超过 90 天的更早备份列为候选。隐私和导入原文件默认不产生候选，除非开发者显式配置对应类型策略。

## 预览、确认和隔离

预览令牌只保存哈希，并绑定操作者/短时会话、主号、机器人、进程实例、策略修订、有序候选 ID、文件与引用修订、总字节数和过期时间。确认采用 compare-and-set；并发确认只有一次成功，过期、复用、重启、候选变化或主号变化都会失败关闭。

确认不会永久删除。文件束在同卷内移入 `storage/trash`，批次依次经历 `prepared`、`moving`、`quarantined`；部分失败进入 `rollback_required` 并逆序恢复。重启会对账中断批次：证据明确时完成隔离或回滚，源和目标同时存在、均不存在或摘要不符时保留两侧并标记 `blocked`，等待人工调查。

每次预览、拒绝、移动、回滚、异常和重启对账都写脱敏审计，并生成 `dashboard_only/suppressed` 主号报告。该报告不会开启汇报 worker，也不会发送 QQ。

## 操作边界

- 仪表盘只接收 artifact ID，不接受客户端路径。
- 重新扫描是幂等、只读的；纳管旧文件不会移动或改名。
- 隔离历史可查询，但网页不提供永久删除和运行库一键恢复。
- 真正的数据库恢复必须按 `docs/STARTUP_READINESS.md` 离线执行。
