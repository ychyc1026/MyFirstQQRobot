# YCH Bot 总体实施计划

## 总目标

YCH Bot 不是“收到消息后调用一次模型”的脚本，而是一个本机运行、由主控号掌握最终权限、能够解释和回滚每次行为的 QQ 智能体系统。

固定身份：

- 主控号：`2000000001`；
- 机器人号：`2000000002`；
- 管理后台品牌：`YCH`。

## 不可违反的功能契约

以后新增的每项能力必须同时具备以下八个部分，否则不算完成：

1. 后端业务能力与持久化状态；
2. 仪表盘可视化入口；
3. 主控号 QQ 查询或控制命令；
4. 权限校验与最小授权；
5. 开关、暂停和紧急停止；
6. 审批或明确的自动执行策略；
7. 审计记录、来源和执行结果；
8. 失败恢复、导出、删除或回滚路径。

不能只做一个后台按钮，也不能只做一条 QQ 命令。仪表盘与主号是同一控制面的两个入口，共用同一套权限、状态机和审计记录。

## 全局运行模式

| 模式 | 入站消息 | AI 推理 | 普通回复 | 主动任务 | 空间发布 |
|---|---:|---:|---:|---:|---:|
| 停机 | 否 | 否 | 否 | 否 | 否 |
| 观察 | 是 | 否 | 否 | 否 | 否 |
| 影子 | 是 | 是，但不发送 | 否 | 只生成草稿 | 只生成草稿 |
| 审批 | 是 | 是 | 经策略/审批 | 经审批 | 经审批 |
| 自动 | 是 | 是 | 是 | 受规则控制 | 受规则控制 |
| 紧急锁定 | 只保留审计 | 否 | 否 | 冻结 | 冻结 |

模式切换必须在仪表盘和主控 QQ 中同时可见。进入“自动”模式需要主控二次确认；紧急锁定可以立即执行。

## 分阶段交付顺序

每个阶段使用纵向切片：数据模型 → 后端用例 → 主控命令 → 仪表盘 API/页面 → 审计 → 测试。不会等到最后才补可视化。

### 阶段 0：运行时与消息底座（已完成）

- NapCat 4.18.18；
- 统一消息段、WebSocket 入站、HTTP 出站；
- SQLite/WAL、幂等事件、outbox；
- 默认观察模式。

### 阶段 1：用户身份、好友生命周期、历史授权与隐私（下一阶段）

- 首次好友基线快照；
- 新好友事件与不确定状态；
- 用户身份证据合并；
- 每用户历史访问策略；
- 数据保留、导出、删除和冻结；
- 用户中心、隐私中心和主控命令。

验收门槛：无法确定时必须显示“未知”，不能擅自把第一次来消息的人判成新好友；默认不读取历史；任何读取都有授权和审计。

### 阶段 2：人格系统

- 全局、私聊、用户专属人格分层；
- 人格合并优先级和冲突检测；
- 简洁定义区；
- 人格版本、预览、灰度和回滚。

### 阶段 3：记忆系统

- 短期会话、长期事实、偏好、关系事件与摘要；
- 来源、可信度、有效期、冲突和遗忘；
- 用户记忆浏览、编辑、导出和删除。

### 阶段 4：长资料炼化

- 已完成 TXT/Markdown/JSON/CSV/HTML/DOCX/文本 PDF 解析；
- 已完成分块检查点、结构化提取、原文证据校验和失败续跑；
- 已完成“认识用户”与“生成对该用户的人格”两种独立任务；
- 已完成统一预览审批；当前不会从资料自动写永久记忆；
- 已完成默认关闭的串行 worker、指数退避、最大尝试与可视化控制；
- 已完成 worker 暂停跨重启持久化、聊天 JSON/CSV 流式、QQ TXT/HTML/OneBot 导出解析与默认可关闭的扫描 PDF OCR 假引擎；待完成真实 OCR 引擎和模型质量评测。

### 阶段 5：模型网关与回复闭环

- 分别接入对话和图片 API；
- 路由、超时、重试、限额、回退；
- 已完成图片任务本地闭环：审批续期、默认关闭假内容审核和孤儿巡检；真实审核网络关闭；
- 已完成影子推理主号查看/显式重跑；候选仍不进 outbox；真实模型网络关闭；
- 影子运行通过后再逐用户启用真实回复。

### 阶段 6：主动消息与调度

- 已完成按真实日历时间和时区持久化，不依赖程序启动时长；
- 已完成安静时段、频率上限以及跳过/宽限/重新审批三种错过处理；
- 已完成每用户默认关闭策略、主控审批、QQ 命令和认证后台 API；
- 已完成调度 worker、幂等 outbox、发送退避/上限和进程恢复；
- 真实 QQ 联调仍关闭；运行时暂停已跨重启持久化。

- 已完成草稿/审批/真实日历调度、安静时段、限频、不确定发布禁止重试和定向隐私；
