# 本机生产启动与 readiness 手册

## 三个 profile

YCH 把“已经配置”“当前活动”“允许执行”分开记录，不根据按钮状态推测成功：

- `local_start`：数据库、迁移备份、受管目录、管理员认证、监听端口和 worker 上限可安全启动。
- `offline_shadow`：模型网络、QQ 外发、空间发布/资料读取均关闭，影子上下文保持用户隔离。
- `controlled_real_effect`：只针对一个明确能力检查精确机器人身份、OneBot 连接、总开关、worker 生命周期、持久暂停、急停、主号授权和证据新鲜度。

readiness 是必要条件，不是自动授权。即使 profile 通过，逐用户隐私授权、额度、审批、安静时段、内容策略和幂等检查仍会独立拒绝操作。

## 安全启动顺序

1. 保持 `.env.example` 中所有网络、外发、空间和 worker 开关为 `false`，只填写本机管理员令牌。
2. 运行启动器预检。预检只读数据库和目录并检查端口，不创建运行库，也不连接 NapCat、模型或搜索。
3. 若旧库需要迁移，确认 `YCH_MIGRATION_BACKUP_ENABLED=true`；启动会先生成并复验一致性备份，失败即停止。
4. 启动后台，检查仪表盘顶部 `local_start` 为通过；“未评估、过期、未知、阻止”均不能当作通过。
5. 先使用 `offline_shadow` 验证上下文、人格、记忆、资料和候选，确认 outbox 没有真实投递。
6. 模型资格鉴定、观察入站、主号私聊 shadow、批准后发送和 limited_auto 均已收口。本机生产上限可以是 `auto` 且外发打开；运行时允许机器人 `2000000002` 的全部私聊，以及该机器人所在群在真实 `@` 时。用机器人 `2000000002` 扫码，不要用主号。搜索和文生图保持关闭。
7. 联调时一次只选择一个真实效果。打开搜索、文生图、隐私执行或 OCR 必须再点名。
8. 若要停自动发送，把请求模式改回 `limited_auto` 或更低，或关闭外发。

## 证据与故障

- 启动器证据绑定配置指纹、进程实例和绝对过期时间。服务重启、Windows 休眠后的墙钟跳变或证据过期都必须重新检查。
- 当前进程占用自己的管理端口可被识别；其他进程占用会阻止启动。
- OneBot 登录 QQ 必须精确等于机器人 `2000000002`。仅配置 token、仅建立连接或连到其他 QQ 都不通过。
- 持久暂停和紧急暂停优先于模式、allowlist 与审批；恢复 worker 不等于打开能力。
- worker 中断、连接断开或调用结果不确定时不自动重发；先在消息链路和操作日志中确认状态。

## 回滚

数据库回滚必须离线执行：停止 YCH、NapCat 连接和全部 worker，保留故障库，核验目标备份的 SHA-256、manifest 与 `quick_check` 后再人工选择。仪表盘不会直接覆盖运行库。受管文件隔离回滚见 `docs/MANAGED_ARTIFACT_RETENTION.md`。

主号私聊可发送 `/帮助` 查看控制命令分区。该命令只读，不会打开任何模型、外发、历史、空间或 worker。

## 模型资格与主号只读

- 付费鉴定只能在已认证仪表盘 `/models` 预览并确认。QQ 文本里的「确认」「预览」不会被解析成鉴定命令。
- `/模型 状态` 只复用仪表盘脱敏决定，不能启动运行。`can_start_paid_run` 恒为否。
- 鉴定通过不会把 `local_start` / `offline_shadow` / `controlled_real_effect` 当成生产授权，也不会打开模型网络或外发。
