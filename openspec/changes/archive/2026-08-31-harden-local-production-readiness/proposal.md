## Why

YCH 已具备回复运行时、数据库迁移保护和多类本地 worker，但“这台电脑现在是否适合进入影子或真实联调”仍分散在多个页面、配置项和日志中；隐私归档等敏感本地文件也缺少统一、可审计的保留管理。现在需要先把启动与真实效果前的证据收成一个失败即关闭的门槛，再继续模型和 OneBot 联调。

## What Changes

- 新增本机生产 readiness 聚合器，统一检查数据库预检与备份、端口占用、NapCat/OneBot 身份和连接、管理令牌配置、模型路由、外发开关、持久暂停、worker 生命周期及证据新鲜度。
- 区分“可启动本地服务”“可运行无网络影子”“可进行受控真实效果”三个 profile；每个 profile 返回结构化 blocker、warning 和证据时间，不用一个模糊的健康布尔值。
- 在应用启动和每个真实效果边界重新检查适用 profile；配置存在不等于能力已启用，状态过期或不确定时失败关闭。
- 新增受管文件清单与保留工作流，覆盖迁移备份、隐私导出/删除归档、导入原文件归档及其可恢复隔离区；每次操作前重新验证路径、大小、SHA-256/manifest 和引用状态。
- 清理只允许“预览 → 当前状态确认 → 移入项目内可恢复隔离区”，禁止自动永久删除、禁止网页一键覆盖运行数据库，候选变化后旧确认立即失效。
- 扩展系统设置与隐私审计页，显示 readiness 总清单、证据时间、阻塞项、受管文件占用、保留候选、隔离记录和审计结果；仪表盘不承担后端授权。
- 增加主号可读的异常汇报摘要，但本变更不启用真实主号投递，只产生现有 durable report/outbox 可消费的安全事件。
- 增加无真实网络、临时数据库和临时文件树下的启动、休眠/重启、端口冲突、证据过期、文件篡改及清理竞态验收。
- 更新运行手册和现状文档，消除已经实现的迁移备份保留策略仍被列为待办的状态漂移。

本变更不启用真实 QQ、模型网络、历史读取、主动消息、QQ 空间或任何真实外发。它不自动永久删除文件；唯一新增的文件移动是经过当前状态确认后进入项目内可恢复隔离区。

## Capabilities

### New Capabilities

- `local-production-readiness`: 本地启动、无网络影子和受控真实效果 profile 的聚合检查、证据新鲜度、失败关闭及重启语义。
- `managed-artifact-retention`: 受管备份/归档清单、重新校验、保留候选、修订绑定确认、可恢复隔离和审计。

### Modified Capabilities

- `safety-controls`: 真实效果边界除现有独立开关外，还必须通过匹配 bot、当前进程和新鲜证据的 readiness profile；受管文件清理继续失败关闭且不得静默永久删除。
- `dashboard-operations`: 系统设置与隐私审计必须展示结构化 readiness、证据来源和受管文件状态，并通过同一后端预览/确认服务执行操作。
- `identity-privacy`: 隐私导出、删除归档和导入原文件归档必须具有明确保留分类、引用保护、完整性复核与可审计隔离语义。

## Impact

- 后端增加 readiness/retention 领域契约、聚合服务、文件清单仓储、修订绑定预览确认和审计事件；现有数据库预检服务成为其中一个证据提供者而不是被替换。
- SQLite 需要加法迁移保存检查快照、受管文件元数据、隔离批次、确认修订和操作结果；旧备份与隐私产物通过只读扫描纳管，不在迁移中移动或删除。
- FastAPI 增加认证的 readiness 详情、刷新、保留清单、预览和隔离端点；所有 DTO 脱敏，不返回令牌、密钥、原始私聊正文或任意绝对路径。
- 系统设置、隐私审计和应用壳层消费同一 readiness DTO；主号汇报只记录安全摘要和关联 ID。
- 测试使用临时端口、临时 SQLite、假 NapCat/模型/transport 和临时文件树，明确断言真实网络客户端未被构造或调用。

## Risks

- readiness 快照可能在检查后变旧：真实效果边界按 profile 要求重新读取关键证据并校验 revision/TTL，不能只信页面快照。
- 文件候选可能在预览后变化：确认绑定候选摘要、引用 revision 和进程实例，任何差异都拒绝执行。
- 隐私删除归档长期保留会反向增加敏感面：先提供可见分类和隔离，不在未明确永久清理政策前自动清除。
- Windows 睡眠、端口重绑定或 NapCat 重连会让旧证据失效：使用绝对时间、实例 ID 和连接身份重新判定，不按进程运行时长推断健康。

## Migration

- 仅增加表和索引；迁移前继续使用现有 SQLite 完整性检查与验证备份门槛。
- 首次启动只扫描并登记受管文件，不移动、不重命名、不删除现有文件，也不自动提升任何运行模式。
- 回滚时停止相关 worker，保留新增表和隔离目录证据；旧版本可忽略加法表。需要恢复数据库时仍必须离线使用已验证迁移备份，网页不直接覆盖运行库。

## User Decisions

- 本变更先实现可恢复隔离，不定义自动永久清空隔离区；永久销毁时限与审批规则留给后续单独决策。
- 模型供应商、各模型 ID、真实 OneBot 连接顺序和真实效果开放范围不在本变更中决定。
